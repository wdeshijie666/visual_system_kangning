# 模拟 PLC + 真机/虚拟 RVC + 真实算法 — 配置与测试

目标组合：**模拟 PLC**、**一台真实 RVC + 一台虚拟 RVC**、**真实点云算法服务**、**模拟产线跑周期**。

运行目录以 Release 为准：

`visual_system/build/apps/visual_system/Release/`

---

## 关键原则

| 目标 | 正确做法 | 错误做法 |
|------|----------|----------|
| 真机 + 虚拟混用 | `runMode: "production"`，虚拟相机序列号用 `STUB_...` | `runMode: "simulation"`（**所有**相机都会变 Stub） |
| 模拟 PLC | 当前工程 `VISION_PLC_ENABLE_LIBPLCTAG=OFF`，走 **MemoryTransport**，无需真 PLC | 打开 libplctag 却不接网关 |
| 真实算法 | `useShm: true` + `algo_config.json` 中 `pipelineSimulation.enabled: false`、`usePointCloudAlgo: true` | 开启 pipeline 仿真（固定假结果） |
| “产线运行” | MemoryTransport 下点「启动」后按 `simAutoTriggerIntervalSec`（默认 30s）交替注入 R05/R09 | `"simAutoTrigger": false` 又指望自动周期 |

---

## 一、配置清单

### 1. `config/setting.json`

```json
"runMode": "production",
"stations": {
  "r05": { "enabled": true, "cameras": ["rvc_01"], "robots": ["R05", "R07"] },
  "r09": { "enabled": true, "cameras": ["rvc_02"], "robots": ["R09"] }
},
"algo": {
  "useShm": true,
  "transferDepth": true,
  "programDir": "alg_program",
  "programExe": "mock_algo_service.exe",
  "channels": {
    "r05": {
      "shmName": "Local\\VisualSystemAlgo_R05_v3",
      "mutexName": "Local\\VisualSystemAlgoMutex_R05_v3"
    },
    "r09": {
      "shmName": "Local\\VisualSystemAlgo_R09_v3",
      "mutexName": "Local\\VisualSystemAlgoMutex_R09_v3"
    }
  }
}
```

说明：

- `plc.gateway` 可保留；MemoryTransport 下不连真机也会 Connect 成功。
- 只测单工位时，把另一边 `enabled: false` 即可。

### 2. `config/devices.json`（真机 + 虚拟）

```json
{
  "cameras": [
    { "id": "rvc_01", "type": "rvc", "serial": "G2GM150B660", "station": "r05" },
    { "id": "rvc_02", "type": "rvc", "serial": "STUB_RVC_02", "station": "r09" }
  ]
}
```

- 真机：真实 SN（示例 `G2GM150B660`，按现场修改）。
- 虚拟：序列号必须以 `STUB_` / `stub_` 开头；否则 production 下会按真机去连并失败。

### 3. `alg_program/algo_config.json`（真实算法）

```json
"pipelineSimulation": { "enabled": false },
"usePointCloudAlgo": true,
"pointCloudConfig": "config.json"
```

同目录还需真实算法用的 `config.json`（及模型/标定等依赖）。仅关 pipeline 仿真不够，缺 `config.json` 时点云算法会失败。

通道名须与 `setting.json` 的 `algo.channels` 一致。

## 二、测试步骤

### 准备

1. 真机 RVC 上电、链路正常；`RVC.dll` 已在 exe 目录。
2. 从 `Release` 启动 `VisualSystem.exe`（工作目录即 Release）。
3. 启动日志应类似：
   - `rvc_01` … **成功**（无「仿真」后缀）→ 实机
   - `rvc_02` … **成功（仿真）** → Stub
   - 算法进程拉起；双通道 SHM 就绪

若 `rvc_01` 也带「仿真」，检查 `runMode` 是否误为 `simulation`，改回 `production` 后重启。

### 路径 A：手动触发（推荐）

不依赖 PLC 边沿，最贴近「模拟产线单周期跑通」：

1. **不要依赖**「启动」后的自动触发（MemoryTransport 无上升沿）。
2. 手动触发 **R05**：真机采图 → SHM → 真算法 → 写 MemoryPLC → UI 刷新。
3. 手动触发 **R09**：Stub 图 → 真算法 → 写 PLC → UI 刷新。
4. 核对：
   - R05：实机采集、算法结果合理、落盘 `data/日期/`。
   - R09：仿真相机、周期完成。
   - 状态栏类似 `周期完成 … algo=1 plc=1`，日志含 `耗时=xxms`。

### 路径 B：点「启动」做产线轮询（Memory 自动触发）

1. `setting.json` 中保持 `simAutoTrigger: true`（默认）、`simAutoTriggerIntervalSec: 30`。
2. 点 **启动**：Connect MemoryPLC + 心跳 + **循环注入 R05/R09 触发**（交替，默认 30s）。
3. 控制台 / stderr 可见 `[PLC仿真] 注入触发` 与 `收到视觉结果`。
4. 真机 AB PLC 接入步骤见 [`真机PLC与Memory触发注入.md`](./真机PLC与Memory触发注入.md)。

### 失败对照

| 现象 | 检查 |
|------|------|
| 两台都是仿真 | `runMode` 是否为 `production` |
| 真机连失败 | SN、RVC 运行时、工位 `enabled` |
| 算法全零/超时 | `pipelineSimulation.enabled`、`config.json`、SHM 名是否一致 |
| 点启动失败 | 看日志 PLC Connect（Memory 一般应成功） |
